GitHub Web Interface for Internet-Draft Authoring

IETF-126 Hands-on Tutorial Cheat Sheet

1. Create Your Draft Repository

Template Repository

github.com/martinthomson/internet-draft-template

  1. Open the template repository.
  2. Click Use this template.
  3. Select Create a new repository.
  4. Enter repository name and description.
  5. ✅ Check Include all branches.
  6. Click Create repository.
Important: Ensure Include all branches is selected.

2. Create the Initial Draft

  1. Open the draft file (draft-*.md or .xml).
  2. Click Edit this file (✏).
  3. Rename the filename.
  4. Rename the draft name inside the file.
  5. Update:
    • Title
    • Authors
    • Affiliations
    • Email addresses
    • Abstract
  6. Click Commit changes....
  7. Select Commit directly to the main branch.
  8. Click Commit changes.

3. Add Co-authors / Contributors

Settings → Collaborators & teams → Add people
  1. Open Settings.
  2. Select Collaborators & teams.
  3. Click Add people.
  4. Enter GitHub username.
  5. Send invitation.

4. Create an Issue (Optional)

Issues → New issue
  1. Open Issues.
  2. Click New issue.
  3. Enter title and description.
  4. Add labels and assignees (optional).
  5. Click Create issue.

Suggested labels

  • editorial
  • clarification
  • design change
  • needs discussion
  • has PR
  • resolution
  • no action needed

5. Edit the Draft Using a Pull Request

  1. Open the draft file.
  2. Click Edit this file.
  3. Make changes.
  4. Click Commit changes....
  5. Select:

    Create a new branch for this commit and start a pull request
  6. Click Propose changes.
  7. Review summary.
  8. Click Create pull request.
  9. Enter title and description.
  10. Click Create pull request.

6. Link a Pull Request to an Issue

Add one of the following lines to the PR description:

Fixes #12

Closes #12

Resolves #12

GitHub will automatically close the issue when the PR is merged.

7. Request Reviews

Pull Request → Reviewers
  1. Open the Pull Request.
  2. Locate Reviewers on the right side.
  3. Click the reviewer selector.
  4. Select reviewer(s).
  5. Optionally leave a comment asking for review.

8. Review a Pull Request

  1. Open the Pull Request.
  2. Select Files changed.
  3. Hover over a line.
  4. Click +.
  5. Add a comment or suggestion.
  6. Click:
    • Start a review
    • or Add single comment
  7. Click Review changes.
  8. Select:
    • Comment
    • Approve
    • Request changes
  9. Click Submit review.

9. Merge the Pull Request

  1. Open the Pull Request.
  2. Verify:
    • Review completed.
    • Checks passed ✅.
  3. Click Merge pull request.
  4. Click Confirm merge.

10. Resolve Merge Conflicts

  1. Click Resolve conflicts.
  2. Edit conflicting sections.
  3. Click Mark as resolved.
  4. Click Commit merge.

11. Check the Build

Actions
  1. Open Actions.
  2. Verify workflow completed successfully ✅.
  3. Open the generated Editor's Copy.
  4. Check:
    • Formatting
    • References
    • Figures
    • Markdown rendering

Common Problems

  • Formatting errors
  • Broken references
  • Markdown syntax issues

SVG Support:
github.com/cabo/kramdown-rfc/wiki/SVG

12. Submit a New Draft Version

Releases → Create a new release
  1. Open Releases.
  2. Click Create a new release.
  3. Create a tag.
  4. Click Publish release.
  5. Watch for submission email.
  6. Confirm the Datatracker email.
Important:
Tag name must exactly match the draft name.

Submission Checklist

  • ✅ Build succeeds
  • ✅ Editor's Copy looks correct
  • ✅ Draft email matches Datatracker account
  • ✅ Tag name matches draft name
